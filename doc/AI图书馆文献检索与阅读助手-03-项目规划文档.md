## 二、项目难点与解决方案

### 2.1 文献解析质量不稳定

问题：

不同 PDF 或 Word 文献的排版差异较大，可能导致正文提取不完整、段落混乱或元数据缺失。

解决方案：

1. 对 PDF、Word 分别设计解析策略；
2. 元数据允许用户手动修改；
3. 解析失败时保留文件并提示用户补充信息；
4. 记录解析状态和失败原因；
5. 优先保证毕设演示场景中的标准 PDF 文献效果。

### 2.2 LLM 可能生成不准确内容

问题：

LLM 在摘要或问答时可能出现不准确或脱离原文的内容。

解决方案：

1. 使用 RAG 方式限制模型基于文献片段回答；
2. 问答结果展示来源文献和参考片段；
3. Prompt 中明确要求不能编造文献不存在的信息；
4. 对 AI 输出增加免责声明，定位为辅助阅读；
5. 保存 AI 调用日志便于复查。

### 2.3 向量检索实现复杂

问题：

向量索引、文本切分和相似度检索对毕设项目有一定实现难度。

解决方案：

1. 文本切分先按段落或固定长度实现；
2. 向量数据可先保存在数据库或专用向量库中；
3. 初期使用关键词检索 + 向量检索混合方案；
4. 优先完成单篇文献问答，再扩展到多文献问答；
5. 将向量检索模块独立封装，便于后续替换实现。

### 2.4 文件存储和访问权限控制

问题：

文献文件可能包含用户私有资料，需要防止越权访问和非法下载。

解决方案：

1. 文件统一存储在 RustFS 中；
2. 数据库保存文件归属和可见范围；
3. 下载接口先校验权限，再返回文件访问地址；
4. 私有文献仅上传者可访问；
5. 公开文献需管理员审核后展示。

### 2.5 AI 调用成本和响应速度

问题：

文献摘要、问答和对比分析需要调用 LLM，可能存在响应慢或成本较高的问题。

解决方案：

1. 文献摘要生成采用异步任务；
2. 对摘要、引用和常见问答结果进行缓存；
3. 限制单次问答上下文长度；
4. 对用户调用频率进行限制；
5. AI 调用失败时提供普通检索和人工笔记功能。

## 三、项目创新点

1. 将 LLM 引入图书馆文献阅读场景，实现文献摘要、问答、对比和笔记辅助。
2. 结合 RAG 技术，使 AI 回答基于文献原文片段，提高回答可追溯性。
3. 支持自然语言文献检索，降低用户检索关键词选择门槛。
4. 设计文献阅读闭环，覆盖上传、解析、检索、阅读、笔记、引用和统计。
5. 使用 RustFS 对象存储管理文献文件，提高文件管理能力和扩展性。
6. 为管理员提供文献使用统计和 AI 运营分析报告，辅助资源建设决策。

## 四、预期成果

项目完成后，应形成以下成果：

1. 一套基于 Spring Boot + Vue 的前后端分离系统；
2. 支持文献上传、存储、解析、检索和阅读；
3. 支持 LLM 文献摘要、自然语言检索、文献问答和多文献对比；
4. 支持阅读笔记、收藏、引用管理和阅读历史；
5. 支持管理员文献审核、用户管理、分类管理和数据统计；
6. 支持 RustFS 文件存储；
7. 具备可演示的核心业务流程；
8. 形成毕业论文、测试报告、系统截图和答辩 PPT 材料。
