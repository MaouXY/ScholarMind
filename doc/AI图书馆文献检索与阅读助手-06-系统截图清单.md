# AI 图书馆文献检索与阅读助手 — 系统截图清单

本文档用于毕业论文「系统实现」与「系统测试/运行效果」章节的配图准备，按**截图顺序**列出页面、
每张图要体现的功能点（也即答辩讲解点）与建议文件名。照此执行一遍即可集齐论文所需配图。

## 一、截图前准备

1. **环境**：MySQL(3306)、RustFS(9990)、Milvus(19530) 均已启动；后端 `mvn spring-boot:run`（8992）、前端 `npm run dev`（5173）。
2. **数据**：已执行 `sql/00~08` 脚本；如需「下载原文」有内容，再跑一次 `pwsh -File scripts/seed-demo-files.ps1`；
   如需向量检索有结果，管理端执行一次 `POST /api/v1/admin/rag/literature-vectors/rebuild`（或在文献详情页点「重建索引」）。
3. **账号**：`admin`（管理端）、`student01`（学生端）、`teacher01`（教师端），密码统一 `123456`。
4. **规范建议**：
   - 浏览器窗口宽度 ≥ 1440px、缩放 100%，深色主题全部统一（避免论文里明暗混排）；
   - 截图只保留浏览器内容区（不带书签栏/桌面），必要时用开发者工具的设备模拟固定尺寸；
   - 同一功能的多状态图（如"审核前/审核后"）保持窗口尺寸一致；
   - 涉及个人信息的页面用演示数据即可，不要出现真实姓名/手机号。
5. **命名规范**：`图<章-序>_<模块>_<要点>.png`，例如 `图4-3_学生端_混合检索对比.png`。
6. **务必确认页面数据非空**：先执行「演示数据」相关脚本，避免出现空列表、全 0 图表。

## 七、注意事项

1. **先备数据再截图**：空列表与全 0 图表最影响观感，务必先跑演示数据脚本与（可选的）向量重建。
2. **AI 相关图**：若截图当刻模型不可用，页面会走本地兜底，仍然可截；但若要展示"真实 AI 生成"，
   请确认运营报告页显示的是「AI 生成」而非「本地兜底」标签。
3. **录屏替代**：答辩若允许，建议对"混合检索对比 + PDF 正文解析"两条链路各录一段 30~60 秒屏，
   比静态图更有说服力。
4. **答辩 PPT 复用**：第二节与第三/四节的高频图（登录、检索对比、阅读、AI 问答、管理中心、数据大屏）可直接进 PPT。
