## 一、截图前准备

1. **环境**：MySQL(3306)、RustFS(9990)、Milvus(19530) 均已启动；后端 `mvn spring-boot:run`（8992）、前端 `npm run dev`（5173）。
2. **数据**：依次执行 `sql/00`~`14`（含 `12_admin_literature_upload.sql` 的管理员上传改造、
   `13_literature_metrics_and_folders.sql` 的被引/参考文献/中图法学科/收藏夹、
   `14_seed_subject_and_metrics.sql` 的多学科演示数据）；
   然后跑 `pwsh -File scripts/seed-demo-files.ps1` 与 `pwsh -File scripts/seed-retrieval-demo-files.ps1` 绑定原文；
   最后在管理端执行一次 `POST /api/v1/admin/rag/literature-vectors/rebuild`，让全部文献分块进入 Milvus。
3. **账号**：`admin`（管理端）、`student01`（用户端），密码统一 `123456`。
   教师账号已下线，`student08`~`student10` 即原三个教师账号转换而来，可用其中任意一个演示「普通用户」视角。
4. **规范建议**：
   - 浏览器窗口宽度 ≥ 1440px、缩放 100%，深色主题全部统一（避免论文里明暗混排）；
   - 截图只保留浏览器内容区（不带书签栏/桌面），必要时用开发者工具的设备模拟固定尺寸；
   - 同一功能的多状态图（如「删除前/删除后」）保持窗口尺寸一致；
   - 涉及个人信息的页面用演示数据即可，不要出现真实姓名/手机号。
5. **命名规范**：`图<章-序>_<模块>_<要点>.png`，例如 `图4-3_用户端_混合检索结果.png`。
6. **务必确认页面数据非空**：先执行「演示数据」相关脚本，避免出现空列表、全 0 图表。

## 七、注意事项

1. **先备数据再截图**：空列表与全 0 图表最影响观感，务必先跑 `sql/14`、演示数据脚本与向量重建
   （`sql/14` 补齐了 7 个非信息科技学科各 2 篇 + 被引次数 + 参考文献，否则结果页左侧学科与类别筛选多半是空的）。
2. **AI 相关图**：若截图当刻模型不可用，页面会走本地兜底，仍然可截；但若要展示「真实 AI 生成」，
   请确认运营报告页显示的是「AI 生成」而非「本地兜底」标签。
