## 三、必须先与客户确认的 8 个问题

1. **教师端推荐给谁看？** 推荐给全班/指定学生/公开？学生端展示位置（我的书房？首页？）——当前无教师端页面，需客户给一张草图或口头描述。
2. **批注建议是给谁看？** 只教师自己看，还是要学生可见？批注粒度是「整篇」还是「分块/段落」？
3. **删除文献是否级联**：读过该书的学生的笔记/收藏/进度要不要一起删？还是删除后仅对未读学生隐藏（保留历史）？
4. **详情页的「删除」按钮**（上传者删自己的文献）客户要求"其余按钮删除"，是否连这个也删？若不删，是否只对上传者显示？
5. **混合检索对比、多文献对比**：界面删除后，后端能力是否保留用于论文/答辩演示？（我们建议保留，仅删入口）
6. **演示文献**：需要多少篇、什么学科主题？是否要求"每篇都有原文 PDF"？（当前 11 篇已发布、12 个原文文件）
7. **「功能未知」四项**：是删除按钮，还是改为自动/加说明？（我们建议改为自动，见 P3）
8. **管理端删掉的指标**（AI 成功率/健康度等）是否还要在论文里出现？后端保留接口即可，还是连数据也不统计？

## 五、风险提示

1. **论文亮点冲突**：混合检索（BM25 + 向量 + RRF）与多文献对比是论文创新点，客户要求删的是**界面**；建议只删 UI、保留接口与实验数据，答辩时用接口/日志/对比脚本展示。
2. **删除文献的级联**若处理不当会造成"检索还能召回已删文献"或统计数字不一致，必须同时清理 Milvus 与分块表。
3. **教师端是从零开始**（现有 `WorkerHomeView.vue` 是模板遗留空壳），不是"完善"，需按新功能评估工期；建议第 3 批单独排期。
4. 界面删除后**论文截图清单**（`doc/...-06`）需要同步更新，避免答辩配图与实际 UI 不符。
