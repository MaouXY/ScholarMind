# AI 图书馆文献检索与阅读助手项目分析与设计文档

## 一、项目需求分析

### 1.1 系统目标

本系统目标是构建一个面向高校学生的 AI 文献检索与阅读辅助平台，实现文献入库、文献解析、文献管理、语义检索、智能摘要、文献问答、阅读笔记、引用管理和后台统计等功能。

系统应实现以下目标：

1. 为管理员提供统一的文献入库入口（题录 9 个字段 + 可选原文），学生端只读；
2. 支持 PDF、Word 等文献文件上传与存储；
3. 利用 LLM 生成摘要、关键词、阅读笔记和问答结果；
4. 支持自然语言检索和基于文献内容的智能问答；
5. 支持用户收藏、阅读记录、笔记和引用管理；
6. 为管理员提供文献上传、分类管理、用户管理和数据统计能力；
7. 形成从文献采集、处理、检索、阅读、沉淀到分析的完整闭环。

### 1.2 用户角色分析

#### 1.2.1 用户端（学生）

学生用户是系统的主要使用者，只读使用平台已入库的文献。

主要需求：

1. 注册登录系统；
2. 检索平台文献资源（学科 / 文献类别 / 关键词）；
3. 查看文献详情和 AI 摘要；
4. 基于文献内容进行智能问答；
5. 收藏文献；
6. 记录阅读笔记；
7. 生成引用格式；
8. 查看阅读历史和学习统计。

#### 1.2.2 教师用户（已作废）

> 客户 2026-10-31《完善需求（改）》要求**删除教师端及其相关功能，只保留用户端和管理端**。
> 该角色已于 2026-11-12 下线：前端删除阅读指导台页面、路由、菜单与登录角色选项；原 3 个教师演示账号转为用户端学生账号（`student08`~`student10`，历史文献归属不变）；后端保留 `TEACHER` 枚举仅用于解析历史 JWT，教师登录返回 `9004 教师端已下线`。

#### 1.2.3 管理员

管理员负责系统后台管理。

主要需求：

1. 管理用户；
2. 管理文献分类（学科）；
3. 上传文献（9 个题录字段 + 可选原文），上传即发布；
4. 编辑文献题录、更换原文；
5. 管理文献资源（含级联删除）；
6. 查看 AI 调用日志；
7. 查看文献阅读统计；
8. 生成平台运营分析报告。

### 1.3 功能需求分析

#### 1.3.1 登录注册模块

功能包括：

1. 用户注册；
2. 用户登录；
3. JWT 身份认证；
4. 角色权限控制；
5. 修改个人信息；
6. 修改密码；
7. 账号启用和禁用。

#### 1.3.2 文献入库与文件管理模块

功能包括：

1. 管理员上传 PDF、Word 等原文（可选，作为附加步骤）；
2. 文件存储至 RustFS 对象存储；
3. 保存题录 9 个字段：标题、作者、来源、文献类别、学科、出版日期、在线公开日期、关键词、摘要；
4. 文献类别为枚举：学术期刊 / 学位论文（硕士）/ 学位论文（博士）/ 报纸；
5. 学科复用平台分类表（`literature_category`），采用中图法八个一级门类：基础科学、工程科技、农业科技、医药卫生科技、哲学与人文科学、社会科学、信息科技、经济与管理科学；
6. 支持文献重新上传原文、编辑题录、删除和下载；
7. 记录上传人（当前管理员）、上传时间和文件大小；
8. 记录被引次数（`citation_count`，管理员录入用于演示）与参考文献原文（`references_text`，供「参考文献」检索维度匹配）。

入库状态：

```text
管理员上传 -> 已发布（status=PUBLISHED）
              ├─ 解析中 -> 已解析（parse_status=INDEXED）
              └─ 摘要中 -> 已生成（summary_status=SUCCESS/FALLBACK）
                     └─ 失败不影响文献入库
```

#### 1.3.3 文献解析模块

系统在文件上传后，对文献内容进行解析。

功能包括：

1. 提取文献正文文本；
2. 提取标题、作者、摘要、关键词等基础信息；
3. 按章节或段落切分文本；
4. 为后续向量检索和文献问答准备文本片段；
5. 记录解析状态和失败原因。

#### 1.3.4 LLM 文献摘要模块

系统调用 LLM 对文献内容生成结构化摘要。

摘要内容包括：

1. 研究背景；
2. 研究问题；
3. 研究方法；
4. 主要结论；
5. 创新点；
6. 关键词；
7. 适合阅读人群。

示例输出：

```json
{
  "background": "该文献关注高校数字图书馆资源使用效率问题。",
  "problem": "传统检索方式难以满足学生自然语言检索和深度阅读需求。",
  "method": "文章采用问卷调查和系统日志分析方法。",
  "conclusion": "智能检索与个性化推荐可提升资源利用率。",
  "keywords": ["数字图书馆", "智能检索", "个性化推荐"]
}
```

#### 1.3.5 自然语言文献检索模块

用户可以用自然语言表达检索需求。

示例输入：

```text
我想找几篇关于高校图书馆智能推荐系统的近五年中文文献
```

系统可解析为：

```json
{
  "keywords": ["高校图书馆", "智能推荐系统"],
  "language": "中文",
  "yearRange": "近五年",
  "sort": "relevance_desc"
}
```

后端根据结构化条件和向量检索结果返回文献列表。

检索门户分两层：

1. **首页（`/student/home`）**：页面正中只有**一个检索栏**——左侧「检索方式」下拉（文献检索 / 智能问答）+ 第二段下拉（文献检索时为主题 / 关键词 / 全文 / 作者 / 摘要 / 参考文献 / 文献来源七个维度，智能问答时为自然语言 / 混合两种召回方式）+ 输入框 + 提交按钮，回车或点击跳转检索结果页。两种方式共用一个输入框，靠切换方式复用；首页**不设分类检索面板**，学科与年度筛选统一放在检索结果页左侧。
2. **检索结果页（`/student/search`）**：URL query 是唯一真源，刷新与分享可复现。左侧为学科 + 年度（2017-2026）辅助分类，顶部为文献类别（学术期刊 / 学位论文（硕士）/ 学位论文（博士）/ 报纸），每条结果显示题名、作者、来源、发表时间、文献类别、被引次数与下载次数。

#### 1.3.6 语义检索模块

系统将文献正文切分为文本片段并生成向量索引。用户输入问题后，系统检索最相关的文献片段，再交由 LLM 生成回答或推荐文献。

功能包括：

1. 文献片段切分；
2. 文本向量生成；
3. 向量索引存储；
4. 相似片段召回；
5. 返回相关文献和片段来源。

#### 1.3.7 文献详情与阅读模块

**详情页（`/student/literature/{id}`）**按要求保持简洁，只展示题名、作者、来源、摘要、关键词、学科、在线公开时间，并提供四类动作：

1. HTML 阅读（跳转阅读页）；
2. PDF 下载（未绑定原文时按钮置灰并给出原因提示）；
3. 引用参考文献（GB/T 7714 / APA / MLA 三种格式，可收藏与导出）；
4. 收藏（可选收藏夹，弹层内选择目标收藏夹，不选则进默认收藏夹）。

**HTML 阅读页（`/student/literature/{id}/read`）**为三栏布局：

1. 左侧目录：AI 摘要、摘要、关键词、正文各段，点击滚动跳转并同步当前段号；
2. 中间正文：文献题录、AI 摘要（分节渲染）、摘要、关键词，以及**内嵌原文**——通过 `GET /literatures/{id}/preview` 换取 RustFS 预签名地址后用 `<iframe>` 由浏览器原生渲染（PDF 走内置阅读器、纯文本按 `charset=utf-8` 渲染），可全屏或另行下载；分块正文降级为「切分索引」，只展示首行用于目录定位与问答引用，不再作为正文展示；
3. 右侧：智能问答（建议问题、提问、引用片段、历史问答）与阅读笔记（新建 / 编辑 / 删除）两个标签页。

预览接口与下载接口同权限、同预签名方式，但**不累加 `download_count`**，并显式覆盖 `response-content-type`（`text/*` 补 `charset=utf-8`）与 `response-content-disposition: inline`，保证内联渲染不乱码、不被当成下载。

AI 摘要落库时是结构化 JSON（`background / problem / method / conclusion / innovation / suitableReaders / keywords`），前端由 `utils/summary.ts` 解析、`components/AiSummaryPanel.vue` 渲染为「研究背景 / 研究问题 / 研究方法 / 主要结论 / 创新点 / 适合读者 + 主题词」，解析失败时退回纯文本展示。

阅读进度按当前分块位置换算并自动保存（滚动节流 + 1.5 秒防抖 + 离开页面强制落库）。

#### 1.3.8 文献智能问答模块

用户可围绕单篇文献或多篇文献进行提问。

示例问题：

```text
这篇文章主要用了什么研究方法？
```

示例回答：

```text
根据文献内容，该文章主要采用问卷调查和系统日志分析方法，对学生使用数字图书馆资源的行为进行统计，并分析影响资源利用率的因素。
```

系统应要求回答基于文献内容生成，并展示参考片段或文献来源，避免模型脱离资料编造。

#### 1.3.9 多文献对比分析模块

用户可以选择多篇文献，让系统对比其研究主题、研究方法、结论和不足。

功能包括：

1. 选择多篇文献；
2. 生成对比表格；
3. 总结共同研究方向；
4. 提取差异点；
5. 输出后续研究建议。

#### 1.3.10 阅读笔记模块

功能包括：

1. 创建文献阅读笔记；
2. 记录重点内容、疑问、观点和引用摘录；
3. AI 辅助生成笔记模板；
4. AI 根据问答记录生成阅读总结；
5. 支持笔记编辑、删除和导出。

#### 1.3.11 引用管理模块

功能包括：

1. 提取文献引用信息；
2. 生成 GB/T 7714、APA、MLA 等引用格式；
3. 收藏引用；
4. 复制引用文本；
5. 导出参考文献列表。

#### 1.3.11.1 我的书房（收藏夹）模块

「我的书房」（`/student/shelf`）分收藏、阅读历史、笔记三个标签页。其中收藏页采用**两层导航**：

1. 第一层（收藏夹列表）：只展示收藏夹条目卡片（「全部收藏」「未分类」+ 各自定义夹），每张卡显示名称、文献数量与说明，并提供新建、重命名、删除；点卡片进入第二层。
2. 第二层（夹内文献）：顶部返回「全部收藏夹」+ 当前夹名，下方是文献卡片（标题/作者/学科/所属夹/阅读量 + 移动到 / 查看详情 / 在线阅读 / 取消收藏）与分页。
3. 新建、重命名、删除收藏夹（同一用户下名称唯一，重名返回 14109）；
4. 收藏时可指定收藏夹，不指定则归入默认收藏夹（首次收藏自动创建）；
5. 已收藏文献可在收藏夹之间移动（单归属，一篇文献只属于一个收藏夹）；
6. 删除收藏夹时夹内收藏退回「未分类」，收藏记录本身不删除。

#### 1.3.12 推荐模块

系统根据用户阅读历史、收藏记录、检索记录和文献标签推荐相关文献。

推荐策略：

1. 基于关键词和标签推荐；
2. 基于同分类热门文献推荐；
3. 基于用户阅读历史推荐；
4. 基于向量相似度推荐。

#### 1.3.13 文献上传与维护模块

管理员上传文献后即发布，无需审核（2026-11-15 客户口径调整，原「文献审核模块」下线）。

功能包括：

1. 填写题录 9 个字段（标题 / 作者 / 来源 / 文献类别 / 学科 / 出版日期 / 在线公开日期 / 关键词 / 摘要），另可补充被引次数与参考文献原文（后者用于「参考文献」检索维度）；
2. 可选上传原文，上传后自动解析建索引并生成 AI 摘要；
3. 查看文献库列表，按关键词与文献类别筛选；
4. 编辑文献题录、更换原文；
5. 删除文献（级联清理分块、收藏、阅读历史、笔记、引用、问答、对象与向量）。

#### 1.3.14 后台统计模块

统计内容包括：

1. 用户总数；
2. 文献总数；
3. 文献类别分布；
4. 热门检索关键词；
5. 热门文献分类（学科）；
6. 文献阅读次数排行；
7. AI 问答调用次数与成功率；
8. 用户阅读活跃度。

### 1.4 核心业务闭环

系统完整闭环如下：

```text
管理员上传文献（题录 9 字段，可选原文）
   ↓
RustFS 存储文件（可选）
   ↓
系统解析文献文本（无原文则回退题录）
   ↓
自动生成文献摘要、关键词和向量索引
   ↓
用户自然语言检索文献
   ↓
用户阅读文献并进行智能问答
   ↓
生成阅读笔记和引用格式
   ↓
系统记录阅读行为
   ↓
后台统计分析资源使用情况
```

## 二、非功能需求分析

### 2.1 安全性

1. 使用 JWT 实现登录认证；
2. 使用 Spring Security 实现角色权限控制；
3. 文献上传与编辑仅管理员可调用（`requireAdmin`），用户端只读；
4. 管理员接口与普通用户接口隔离（`/api/v1/admin/**` → `hasRole("ADMIN")`）；
5. 文件上传限制类型和大小；
6. 防止越权访问历史私有文献（`ensureReadable` 兼容老数据）；
7. AI 调用记录入库，便于审计和排查。

### 2.2 易用性

1. 文献上传流程应简洁；
2. 文献摘要应结构化展示；
3. 检索入口同时支持关键词检索和自然语言检索；
4. 问答结果应展示来源文献或参考片段；
5. 阅读笔记支持快速编辑和导出。

### 2.3 可维护性

1. 前后端分离；
2. 后端采用 controller、service、mapper 分层；
3. AI 能力封装为独立服务；
4. 文献解析、向量检索和 LLM 调用解耦；
5. 日志记录完整；
6. 接口风格统一。

### 2.4 性能需求

1. 文献列表分页查询；
2. 大文件上传限制和进度提示；
3. 文献解析和摘要生成采用异步任务；
4. 热门文献和热门关键词可缓存；
5. 文献文件统一存储在 RustFS 对象存储中；
6. AI 调用结果可缓存或保存，减少重复调用。

### 3.4 AI 模块设计

建议设计统一 AI 服务：

```text
AiLiteratureService
├── generateSummary()
├── parseSearchQuery()
├── answerQuestion()
├── compareLiteratures()
├── generateReadingNote()
├── generateCitation()
└── generateOperationReport()
```

AI 模块只负责生成结构化结果，不直接决定权限和业务状态。文献入库、下载、删除等业务操作仍由业务服务和管理员控制。

### 3.5 RAG 流程设计

```text
文献入库（管理员上传题录 + 可选原文）
   ↓
正文文本提取（有原文走 PDF/Word 解析；无原文回退题录与摘要）
   ↓
文本分段
   ↓
生成向量写入 Milvus（不可用时降级 DB_ONLY，检索退化为纯 BM25）
   ↓
检索：BM25 稀疏召回 + 向量稠密召回 → RRF 融合（可选 Bocha 重排）
   ↓
用户提问
   ↓
取融合后前 N 个片段作为证据
   ↓
LLM 基于片段生成回答
   ↓
返回答案、来源片段与三路名次
```

## 五、核心业务流程

### 5.1 文献上传与解析流程

```text
管理员上传文献（题录 9 字段 + 可选原文）
   ↓
文件保存至 RustFS（可选）
   ↓
保存文献基础记录（visibility=PUBLIC、status=PUBLISHED）
   ↓
解析正文（无原文时回退题录语料）
   ↓
生成 AI 摘要和关键词
   ↓
切分文本并生成向量索引
   ↓
文献进入可阅读状态（上传即发布）
```

### 5.2 文献检索流程

系统提供两条检索入口，都从首页同一个检索栏发起、靠「检索方式」切换：**题录检索**（按检索维度对题录字段做 LIKE 精确匹配，学科与年度在结果页左侧筛选）与 **RAG 智能检索**（稀疏 BM25 + 稠密向量 + RRF 融合）。

```text
首页检索栏「检索方式」选「文献检索」，输入关键词并选择检索维度（主题 / 关键词 / 全文 / 作者 / 摘要 / 参考文献 / 文献来源）
   ↓
跳转检索结果页，按维度拼装 WHERE 条件查 literature
   ↓
左侧叠加学科（中图法一级门类）与年度（2017-2026）过滤
   ↓
返回题名、作者、来源、发表时间、文献类别、被引次数、下载次数

首页检索栏「检索方式」切到「智能问答」，输入自然语言需求
   ↓
LLM 解析检索意图（自然语言模式）或直接使用原句（混合模式）
   ↓
BM25 稀疏召回 + Milvus 向量召回
   ↓
RRF 融合排序（可选 Bocha 重排）
   ↓
返回文献列表与命中片段（带稀疏名次 / 向量名次 / RRF 分数）
```

### 5.3 文献问答流程

```text
用户在文献详情页提问
   ↓
系统检索相关文献片段
   ↓
LLM 基于片段生成回答
   ↓
保存问答记录
   ↓
返回答案和来源片段
```

### 5.4 阅读笔记流程

```text
用户阅读文献
   ↓
记录阅读进度
   ↓
用户创建或编辑笔记
   ↓
AI 可根据文献内容生成笔记模板
   ↓
保存笔记
   ↓
支持导出和后续复习
```
