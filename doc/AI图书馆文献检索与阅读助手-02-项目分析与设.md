# AI 图书馆文献检索与阅读助手项目分析与设计文档

## 一、项目需求分析

### 1.1 系统目标

本系统目标是构建一个面向高校学生的 AI 文献检索与阅读辅助平台，实现文献上传、文献解析、文献管理、语义检索、智能摘要、文献问答、阅读笔记、引用管理和后台统计等功能。

系统应实现以下目标：

1. 为学生提供统一的文献资料管理入口；
2. 支持 PDF、Word 等文献文件上传与存储；
3. 利用 LLM 辅助生成摘要、关键词、阅读笔记和问答结果；
4. 支持自然语言检索和基于文献内容的智能问答；
5. 支持用户收藏、阅读记录、笔记和引用管理；
6. 为管理员提供文献审核、分类管理、用户管理和数据统计能力；
7. 形成从文献采集、处理、检索、阅读、沉淀到分析的完整闭环。

### 1.2 用户角色分析

#### 1.2.1 学生用户

学生用户是系统的主要使用者。

主要需求：

1. 注册登录系统；
2. 上传个人文献资料；
3. 检索平台文献资源；
4. 查看文献详情和 AI 摘要；
5. 基于文献内容进行智能问答；
6. 收藏文献；
7. 记录阅读笔记；
8. 生成引用格式；
9. 查看阅读历史和学习统计。

#### 1.2.2 教师用户，可选

教师用户可以上传课程资料、推荐阅读文献、查看课程相关资料使用情况。

主要需求：

1. 上传课程文献资料；
2. 管理推荐阅读列表；
3. 查看学生阅读数据统计；
4. 使用 AI 辅助生成导读问题和阅读任务。

#### 1.2.3 管理员

管理员负责系统后台管理。

主要需求：

1. 管理用户；
2. 管理文献分类；
3. 审核公开文献；
4. 管理文献资源；
5. 查看 AI 调用日志；
6. 查看文献阅读统计；
7. 生成平台运营分析报告。

### 1.3 功能需求分析

#### 1.3.1 登录注册模块

功能包括：

1. 用户注册；
2. 用户登录；
3. JWT 身份认证；
4. 角色权限控制；
5. 修改个人信息；
6. 修改密码；
7. 账号启用和禁用。

#### 1.3.2 文献上传与文件管理模块

功能包括：

1. 上传 PDF、Word 等文献文件；
2. 文件存储至 RustFS 对象存储；
3. 保存文献标题、作者、年份、来源、关键词等元数据；
4. 支持文献封面或首页预览图；
5. 支持私有文献和公开文献两种可见范围；
6. 支持文献重新上传、删除和下载；
7. 记录上传人、上传时间和文件大小。

文件状态：

```text
上传中 -> 待解析 -> 已解析 -> 待审核 -> 已公开
                 ↓        ↓
              解析失败   审核失败
```

#### 1.3.3 文献解析模块

系统在文件上传后，对文献内容进行解析。

功能包括：

1. 提取文献正文文本；
2. 提取标题、作者、摘要、关键词等基础信息；
3. 按章节或段落切分文本；
4. 为后续向量检索和文献问答准备文本片段；
5. 记录解析状态和失败原因。

#### 1.3.4 LLM 文献摘要模块

系统调用 LLM 对文献内容生成结构化摘要。

摘要内容包括：

1. 研究背景；
2. 研究问题；
3. 研究方法；
4. 主要结论；
5. 创新点；
6. 关键词；
7. 适合阅读人群。

示例输出：

```json
{
  "background": "该文献关注高校数字图书馆资源使用效率问题。",
  "problem": "传统检索方式难以满足学生自然语言检索和深度阅读需求。",
  "method": "文章采用问卷调查和系统日志分析方法。",
  "conclusion": "智能检索与个性化推荐可提升资源利用率。",
  "keywords": ["数字图书馆", "智能检索", "个性化推荐"]
}
```

#### 1.3.5 自然语言文献检索模块

用户可以用自然语言表达检索需求。

示例输入：

```text
我想找几篇关于高校图书馆智能推荐系统的近五年中文文献
```

系统可解析为：

```json
{
  "keywords": ["高校图书馆", "智能推荐系统"],
  "language": "中文",
  "yearRange": "近五年",
  "sort": "relevance_desc"
}
```

后端根据结构化条件和向量检索结果返回文献列表。

#### 1.3.6 语义检索模块

系统将文献正文切分为文本片段并生成向量索引。用户输入问题后，系统检索最相关的文献片段，再交由 LLM 生成回答或推荐文献。

功能包括：

1. 文献片段切分；
2. 文本向量生成；
3. 向量索引存储；
4. 相似片段召回；
5. 返回相关文献和片段来源。

#### 1.3.7 文献详情与阅读模块

功能包括：

1. 查看文献基本信息；
2. 查看 AI 摘要；
3. 在线预览文献；
4. 查看章节目录；
5. 查看关键词和标签；
6. 查看相关文献推荐；
7. 收藏文献；
8. 下载文献。

#### 1.3.8 文献智能问答模块

用户可围绕单篇文献或多篇文献进行提问。

示例问题：

```text
这篇文章主要用了什么研究方法？
```

示例回答：

```text
根据文献内容，该文章主要采用问卷调查和系统日志分析方法，对学生使用数字图书馆资源的行为进行统计，并分析影响资源利用率的因素。
```

系统应要求回答基于文献内容生成，并展示参考片段或文献来源，避免模型脱离资料编造。

#### 1.3.9 多文献对比分析模块

用户可以选择多篇文献，让系统对比其研究主题、研究方法、结论和不足。

功能包括：

1. 选择多篇文献；
2. 生成对比表格；
3. 总结共同研究方向；
4. 提取差异点；
5. 输出后续研究建议。

#### 1.3.10 阅读笔记模块

功能包括：

1. 创建文献阅读笔记；
2. 记录重点内容、疑问、观点和引用摘录；
3. AI 辅助生成笔记模板；
4. AI 根据问答记录生成阅读总结；
5. 支持笔记编辑、删除和导出。

#### 1.3.11 引用管理模块

功能包括：

1. 提取文献引用信息；
2. 生成 GB/T 7714、APA、MLA 等引用格式；
3. 收藏引用；
4. 复制引用文本；
5. 导出参考文献列表。

#### 1.3.12 推荐模块

系统根据用户阅读历史、收藏记录、检索记录和文献标签推荐相关文献。

推荐策略：

1. 基于关键词和标签推荐；
2. 基于同分类热门文献推荐；
3. 基于用户阅读历史推荐；
4. 基于向量相似度推荐。

#### 1.3.13 文献审核模块

用户上传公开文献后，需要管理员审核。

功能包括：

1. 查看待审核文献；
2. 查看文献元数据；
3. 查看 AI 摘要和风险提示；
4. 审核通过；
5. 审核驳回；
6. 填写驳回原因。

#### 1.3.14 后台统计模块

统计内容包括：

1. 用户总数；
2. 文献总数；
3. 上传文献数量；
4. 热门检索关键词；
5. 热门文献分类；
6. 文献阅读次数排行；
7. AI 问答调用次数；
8. 文献审核通过率；
9. 用户阅读活跃度。

### 1.4 核心业务闭环

系统完整闭环如下：

```text
用户上传文献
   ↓
RustFS 存储文件
   ↓
系统解析文献文本和元数据
   ↓
生成文献摘要、关键词和向量索引
   ↓
管理员审核公开文献
   ↓
用户自然语言检索文献
   ↓
用户阅读文献并进行智能问答
   ↓
生成阅读笔记和引用格式
   ↓
系统记录阅读行为
   ↓
后台统计分析资源使用情况
```

## 二、非功能需求分析

### 2.1 安全性

1. 使用 JWT 实现登录认证；
2. 使用 Spring Security 实现角色权限控制；
3. 用户只能访问本人私有文献和已公开文献；
4. 管理员接口与普通用户接口隔离；
5. 文件上传限制类型和大小；
6. 防止越权下载他人私有文献；
7. AI 调用记录入库，便于审计和排查。

### 2.2 易用性

1. 文献上传流程应简洁；
2. 文献摘要应结构化展示；
3. 检索入口同时支持关键词检索和自然语言检索；
4. 问答结果应展示来源文献或参考片段；
5. 阅读笔记支持快速编辑和导出。

### 2.3 可维护性

1. 前后端分离；
2. 后端采用 controller、service、mapper 分层；
3. AI 能力封装为独立服务；
4. 文献解析、向量检索和 LLM 调用解耦；
5. 日志记录完整；
6. 接口风格统一。

### 2.4 性能需求

1. 文献列表分页查询；
2. 大文件上传限制和进度提示；
3. 文献解析和摘要生成采用异步任务；
4. 热门文献和热门关键词可缓存；
5. 文献文件统一存储在 RustFS 对象存储中；
6. AI 调用结果可缓存或保存，减少重复调用。

### 3.4 AI 模块设计

建议设计统一 AI 服务：

```text

├── generateSummary()
├── parseSearchQuery()
├── answerQuestion()
├── compareLiteratures()
├── generateReadingNote()
├── generateCitation()
└── generateOperationReport()
```

AI 模块只负责生成结构化结果，不直接决定权限和业务状态。文献审核、公开、下载、删除等业务操作仍由业务服务和管理员控制。

## 五、核心业务流程

### 5.1 文献上传与解析流程

```text
用户上传文献
   ↓
文件保存至 RustFS
   ↓
保存文献基础记录
   ↓
异步解析正文和元数据
   ↓
生成 AI 摘要和关键词
   ↓
切分文本并生成向量索引
   ↓
文献进入可阅读或待审核状态
```

### 5.2 文献检索流程

```text
用户输入关键词或自然语言需求
   ↓
LLM 解析检索条件
   ↓
数据库字段检索 + 向量相似度检索
   ↓
融合排序
   ↓
返回文献列表和相关片段
```

### 5.3 文献问答流程

```text
用户在文献详情页提问
   ↓
系统检索相关文献片段
   ↓
LLM 基于片段生成回答
   ↓
保存问答记录
   ↓
返回答案和来源片段
```

### 5.4 阅读笔记流程

```text
用户阅读文献
   ↓
记录阅读进度
   ↓
用户创建或编辑笔记
   ↓
AI 可根据文献内容生成笔记模板
   ↓
保存笔记
   ↓
支持导出和后续复习
```
