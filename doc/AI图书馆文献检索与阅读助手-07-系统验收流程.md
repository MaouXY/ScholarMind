# AI 图书馆文献检索与阅读助手 — 系统验收流程

本文档用于毕业设计验收 / 答辩现场演示：按顺序执行即可完成一轮完整验收。每条用例含**操作步骤**、
**预期结果**与**实测记录（留空待填）**三列，验收时逐条勾选即可。

> 版本对应 2026-10-31《完善需求（改）》：删除教师端，只保留**用户端**与**管理端**；三种检索模式
> （自然语言 / 语义 / 混合）取代原「混合检索三列对比」区块；管理中心新增「文献库管理 + 删除文献」。
> 改动明细见 `doc/...-10-完善需求改版对照与改造计划.md`。

## 一、验收范围与角色

| 角色 | 覆盖能力 |
| --- | --- |
| 用户 STUDENT | 检索（自然语言/语义/混合三种模式）、文献详情、AI 摘要、在线阅读与进度自动保存、笔记、收藏、引用管理（三种格式）、下载原文、我的书房、智能问答、上传文献并提交审核 |

### 2.1 数据准备

```powershell
# 1) 初始化数据库（首次）：按文件名顺序执行全部脚本（当前为 00~10）
$mysql = 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe'
Get-ChildItem .\ScholarMindApi\src\main\resources\sql\*.sql | Sort-Object Name | ForEach-Object {
  Write-Host "==> $($_.Name)"
  Get-Content $_.FullName -Raw | & $mysql --default-character-set=utf8mb4 -uroot -p<密码> scholar_mind
}

# 2) 为已发布文献上传并绑定原文文件（需 RustFS 在线）
pwsh -NoProfile -File .\scripts\seed-demo-files.ps1

# 3) 为 12 篇检索演示文献绑定原文（正文取自库内分块，保证在线阅读与下载一致）
pwsh -NoProfile -File .\scripts\seed-retrieval-demo-files.ps1

# 4) 把已发布文献分块写入 Milvus，使语义/混合检索的向量路可用（需 Milvus 在线）
curl.exe -X POST http://127.0.0.1:8992/api/v1/admin/rag/literature-vectors/rebuild -H "Authorization: Bearer <管理员 token>"
```

其中两个脚本是本轮改版新增的：

| 脚本 | 作用 | 校验输出 |
| --- | --- | --- |
| `09_retire_teacher_accounts.sql` | 3 个教师账号转用户端（`student08`/`student09`/`student10`，保留 id 以维持文献归属），兜底停用任何残留 `TEACHER` | 末行 `remaining_teacher_accounts = 0` |
| `10_seed_retrieval_demo.sql` | 12 篇检索演示文献 + 36 个正文分块，按术语型 / 改写型 / 混合型三类设计，使三种检索模式结果可区分 | `demo_literature_count=12`、`demo_chunk_count=36`、`chunks_waiting_for_vector=36`（重建后归 0） |

> **A3 / X19 的教师账号从哪来**：`sql/09` 已把三个教师账号转成 `student08`~`student10`，库里 `role='TEACHER'` 的账号为 0，所以直接登录 `teacher01` 会返回 `9001`（用户名不存在）。
> 要复现「教师登录被拒绝」，临时插一个探针账号（注意：不要在插入后再重跑 `sql/09`，其兜底语句会把它停用、届时返回的是 `9002` 而不是 `9004`；验收后删除即可）：
>
> ```sql
> INSERT INTO user_account (id, username, password_hash, nickname, email, role, status, deleted)
> VALUES (9000000000000000001, 'teacher_probe',
>         '$2b$10$kUsC1ZV2DZlUKr0w1GlCeeh05BLAInwjuvUqtNESb2x7q/Z7bSBdi',  -- 123456
>         '教师探针', 'teacher_probe@scholarmind.local', 'TEACHER', 1, 0);
> ```
>
> 登录应返回 `code=9004`；验收后 `DELETE FROM user_account WHERE id=9000000000000000001;` 清理。

## 八、常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后端启动报 `Port 8992 was already in use` | 已有实例在跑 | `Get-NetTCPConnection -LocalPort 8992 -State Listen` 找到 PID 后 `Stop-Process`，或先停止旧实例 |
| 前端启动报端口占用 | 5173 被占 | 关闭占用进程，或修改 `ScholarMindWeb/vite.config.ts` 的 `server.port` |
| 文献上传失败 / 下载提示未绑定文件 | RustFS 未启动或 bucket 不存在 | 启动 RustFS，确认 bucket `scholar-mind` 存在 |
| 「向量检索未就绪」 | Milvus 未启动或分块未写入向量 | 启动 Milvus 后执行 `/admin/rag/literature-vectors/rebuild` |
| Milvus 报 `Incorrect dimension for field 'vector'` | `app.agent.rag.milvus.dimension` 与 embedding 模型实际维度不一致 | 该模型为 **2560**；服务已在写入时自动删表重建，如仍失败请核对配置 |
| AI 摘要/问答提示服务不可用 | Ark Key 或模型名不可用 | 检查 `application.yaml` 的 `app.ai.ark.*`；失败记录可在「AI 调用日志」查看 |
| AI 请求 15 秒就超时 | 前端曾用全局 15 秒超时 | 已改为 AI 专用 120 秒（`AI_REQUEST_TIMEOUT`），若仍超时请确认前端已重新构建 |
| 页面列表为空 / 图表全 0 | 未执行演示数据脚本 | 执行 `sql/00~10`、两个 seed 脚本与向量重建 |
| 中文数据插入报 `Incorrect string value` | mysql 客户端字符集非 utf8mb4 | 执行 SQL 时加 `--default-character-set=utf8mb4` |
| 管理端删除后统计未变 | 前端未刷新或用了旧实例 | 删除成功后会自动并行刷新文献库/待审核/看板；确认后端已重启为新版本 |
